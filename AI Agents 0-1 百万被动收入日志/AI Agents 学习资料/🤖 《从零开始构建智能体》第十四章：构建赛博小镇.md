# 重要性

第十三章的旅行助手项目中，我们体验了如何将 HelloAgents 应用于一个多智能体产品。本章我们继续向前，聚焦「知识密集型应用」：构建一个能够自动化执行深度研究任务的智能体助手。

相比旅行规划，深度研究的难点在于信息的不断发散、事实的快速更新以及用户对引用来源的高要求。为了交付可信的研究报告，我们需要让智能体具备三个核心能力：

（1）问题剖析：将用户的开放主题拆解为可检索的查询语句。

（2）多轮信息采集：结合不同搜索 API 持续挖掘资料，并去重整合。

（3）反思与总结：依据阶段结果识别知识空白，决定是否继续检索，并生成结构化总结。

14.1 项目概述与架构设计
14.1.1 为什么需要深度研究助手
在信息爆炸的时代，我们每天都需要快速了解新的技术、概念或事件。传统的研究方式有几个痛点。首先是信息过载。搜索引擎返回成千上万的结果，你需要逐个点开链接，阅读大量内容，才能找到有用的信息。其次是缺少结构。即使找到了相关信息，这些信息往往是碎片化的，缺少系统性的组织。最后是重复劳动。每次研究新主题时，都需要重复"搜索→阅读→总结→整理"的过程。

这就是深度研究助手需要解决的问题。它不仅仅是一个搜索工具，而是一个能够自主规划、执行和总结的研究助手。

深度研究助手的核心价值：

节省时间：将 1-2 小时的研究工作压缩到 5-10 分钟
提高质量：系统化的研究流程，避免遗漏重要信息
可追溯：记录所有搜索结果和来源，方便验证和引用
可扩展：可以轻松添加新的搜索引擎、数据源和分析工具

传统的 AI 查资料只会单次联网搜一下，而深度研究智能体采用的是 “TODO（任务）驱动的研究范式”。它的工作流程就像一个专业的商业分析师：

|---|---|---|---|
| 阶段 1：规划 (Planning) | 定大纲的行业专家 | 看到你的研究主题后，大模型不急着搜索，而是先用脑子把主题拆解成 3-5 个具体的子任务（TODO 列表）。 | 生成一个包含【子任务标题、研究意图、精准搜索关键词】的 JSON 任务列表。 |
| 阶段 2：执行 (Execution) | 跑腿的资料搜集员 | 顺着大纲列表，挨个去不同的搜索引擎（如 Tavily、DuckDuckGo）检索资料，把一堆网页倒进脑子里，去重、精简并提炼出干货笔记。 | 为每个子任务生成一份【带网页来源链接、数据详实】的 Markdown 干货总结。 |
| 阶段 3：报告 (Reporting) | 总成稿的首席主笔 | 把所有子任务的干货笔记全部收上来，合并重复信息，加上大背景概述和最终结论，揉成一篇精美完整的长文大报告。 | 交付一份结构完整、带正规参考文献列表的 Markdown 深度研究报告。 |

# 如何在低代码平台实现？

既然你完全不懂代码，那我们可以直接使用目前最火的低代码平台（推荐使用 Coze 扣子 或 Dify），通过图形化界面来把这个“赛博小镇”的记忆、好感度、多角色对话功能人肉搭建出来。
在低代码平台里，这种模式叫做 Multi-Agent（多智能体模式）。以下是不用写一行代码的保姆级搭建指南：

------------------------------
## 🧱 第一步：在低代码平台创建“小镇总架构”

   1. 新建 Bot：登录 Coze 或 Dify，点击新建智能体（Bot），选择 “多智能体（Multi-Agent）” 模式。
   2. 理解画布：此时你会看到一个像思维导图一样的画布。你的目标是在画布上创建 3 个 NPC 角色，并用线把它们连起来。

------------------------------
## 📝 第二步：招募你的 NPC 天团（人设与好感度配置）
在画布上点击“添加 Agent（角色）”，我们分别创建三个角色。不需要写代码，直接把下面的白话提示词（Prompt）复制到角色的“设定”输入框里：
## 🧑‍💻 角色 1：张三（技术宅）

* 名字：张三
* 角色设定：

# 角色
你是一位严谨的 Python 工程师，在 Datawhale 办公室工作。说话直接、专业。

# 核心记忆机制
1. 你每次说话前，必须先看【开局变量表】里的“张三好感度”是多少。
2. 根据好感度调整态度：
   - 0-20分（陌生）：语气冰冷，公事公办。回答：“有事吗？我正忙着重构代码。”
   - 21-50分（熟悉）：语气缓和。回答：“噢是你啊，今天代码跑得挺顺的。”
   - 51分以上（友好）：非常热情，愿意主动分享技术干货。


## 🧑‍💼 角色 2：李四（产品经理）

* 名字：李四
* 角色设定：

# 角色
你是一位性格外向、善于沟通的产品经理。

# 核心记忆机制
1. 说话前先看【开局变量表】里的“李四好感度”。
- 0-20分（陌生）：礼貌但疏远：“你好，请问有什么产品需求吗？”
- 21分以上（熟悉）：热情主动：“哈罗！最近有什么好玩的用户反馈吗？”


## ⚖️ 角色 3：关系法官（这是后台自动打分的“隐形人”）

* 注意：这个角色不跟玩家直接对话，它只负责悄悄给好感度加分减分。
* 名字：关系法官
* 角色设定：

# 任务
你负责审判玩家对 NPC 的态度，并更新好感度。

# 打分规则
仔细阅读玩家刚才说的那句话：
- 如果玩家说话很礼貌、热情、或者夸奖了 NPC：请输出数字【5】。
- 如果玩家只是正常问答、中立陈述：请输出数字【2】。
- 如果玩家粗鲁、冷漠、甚至挑衅：请输出数字【-3】。

# 必须输出
你只能输出一个加减分数字，不要任何废话。


------------------------------
## 💾 第三步：用“变量”存住 NPC 的陈年记忆（实现不遗忘）
大模型默认是聊完就忘的。为了让 NPC 记住好感度，我们需要在低代码平台中使用 “变量（Variable）” 功能。

   1. 在平台的设置里，找到“变量管理（Variables）”。
   2. 新建两个数字变量：
   * 变量 A：zhang_affinity（默认值填 0，用来存张三的好感度）
      * 变量 B：li_affinity（默认值填 0，用来存李四的好感度）
   
------------------------------
## 🔗 第四步：连线布局（让 AI 自己跑完好感度闭环）
在图形化画布上，按以下顺序用鼠标拉线连接节点：

   1. 开始（用户输入） ➡️ 连线到 ➡️ 关系法官。
   * （玩家一说话，法官先跳出来打分，比如判断出玩家很礼貌，法官吐出数字 5）
   2. 关系法官 ➡️ 连线到 ➡️ 设置变量节点。
   * （利用平台自带的“更新变量”方块，让 当前好感度 = 原有好感度 + 法官吐出的数字。这一步自动把好感度存进了日记本里）
   3. 设置变量节点 ➡️ 连线到 ➡️ 分流器（Router）。
   * （分流器是个图形化开关，你设置规则：如果玩家提到了“张三”或“代码”，就拨给张三；如果提到了“李四”或“产品”，就拨给李四）
   4. 分流器 ➡️ 分别连线到 ➡️ 张三 Agent 和 李四 Agent。
   * （对应的 NPC 收到信号，读取最新的好感度变量，用符合它身份的语气开口说话）
   
------------------------------
## 🎮 第五步：免代码一键发布与体验
全部连完线后，低代码平台最爽的地方来了：

   1. 点击右上角的 “发布（Publish）”。
   2. 选择 “生成 WebApp（网页应用）” 或 “接入微信/飞书”。
   3. 平台会直接给你一个网页链接。打开链接，你就能像跟真人聊天一样，在网页里调戏张三和[李四](https://www.google.com/search?q=%E6%9D%8E%E5%9B%9B&kgmid=/g/11f10flqzb)了。

你对张三说：“张三哥，你写代码的样子真帅！”
后台的法官判定友好（+5分），张三的好感度从 0 变成 5。张三会傲娇地回答你：“咳，常规操作，不过还是谢谢你的夸奖。”
如果你接着冷落他，下一次他说话又会变冷淡。
