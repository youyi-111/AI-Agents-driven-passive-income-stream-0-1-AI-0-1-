# 编程小白的codex 0-1 指南

> 资料来源： chatgpt

可以，而且我建议你**英文资料为主、中文解释为辅**。因为 Codex、Agents SDK、MCP、Skills 这些东西变化非常快，中文教程很容易半年后就过时。下面这套路线我按你“**完全编程小白，但目标不是成为程序员，而是会指挥 Codex 帮你创造 Agent、自动化工作和赚钱**”来设计。

先给你一个重要结论：**你不需要先系统学编程再学 Codex。** 你真正需要掌握的是一套“AI 项目经理 / Agent 架构师”的能力：知道文件、项目、API、工具、Agent、Skill、MCP 分别是什么；知道怎么把需求说清楚；知道怎么让 Codex 自己搭环境、写代码、测试、修 Bug；最后你只负责判断方向和验收。OpenAI 官方现在也明确把 Codex 定位从纯开发工具扩展到了知识工作、工作流自动化和非技术用户场景。

# 第一阶段：你今天最应该看的

## ① Getting started with Codex

**官方视频：**

https://www.youtube.com/watch?v=px7XlbYgk7I

这是我目前最推荐你第一看的资料。

官方视频会带你走一遍：

> Codex → 安装 → CLI → VS Code → 项目 → AGENTS.md → Prompt → Review

也就是说它不会像很多程序员教程一样一上来：

> Python  
> Node  
> Git  
> Docker  
> terminal  
> environment variable

把你直接劝退。

它是从“**怎么用 Codex 干活**”开始。官方描述里也明确包含 CLI、VS Code extension、workflow、AGENTS.md 和 prompting。

### 你看这个视频时，不要试图听懂所有代码。

你只需要搞懂六件事：

**Project**

就是：

> Codex 工作的文件夹。

以后你可以想象：

```text
我的AI生意
│
├── 产品研究
├── 客户研究
├── 自动发内容
├── competitor research
└── AGENTS.md
```

---

**Terminal**

你现在可以把它理解成：

> 用文字命令控制电脑。

例如：

```text
创建文件
安装软件
运行程序
打开服务器
```

你不需要背命令。

以后可以直接告诉 Codex：

> 我完全不懂 terminal。  
> 需要运行什么命令你自己运行。  
> 每次告诉我你为什么要运行。

---

**Repository / Repo**

暂时理解成：

> 一个软件项目的文件夹。

就够了。

---

**Prompt**

不是“问问题”。

而是：

> 给你的 AI 员工写任务 brief。

---

**Diff**

就是：

> Codex 到底修改了什么。

---

**Test**

就是：

> Codex 做完以后自己检查有没有做坏。

这六个词理解以后，你已经足够开始使用 Codex。

# ② OpenAI 官方 Codex Best Practices

https://learn.chatgpt.com/guides/best-practices

这是我认为**对你价值最高的一篇 Codex 官方文章**。

因为它不是教 coding。

而是在教：

> **怎么管理 Codex。**

OpenAI 给出的一个非常重要的 Prompt 框架是：

**Goal**

你想实现什么？

**Context**

Codex 应该看哪些资料？

**Constraints**

有什么不能做？

**Done when**

达到什么标准才算完成？

以后你给 Codex 的任务最好长这样：

```text
Goal

帮我创建一个每天自动寻找海外高价值AI商业机会的Agent。

Context

我是非技术创业者。
关注Digital Products / AI Agent / Creator Economy。
目标客户为欧美高收入用户。

Constraints

我完全不会编程。
尽量选择简单稳定的技术方案。
不要过度设计。
所有付费API调用必须限制成本。

Done when

1. 每天自动抓取信息
2. 自动判断需求是否正在增长
3. 自动输出Top 10机会
4. 自动分析市场、竞争和变现方式
5. 给我生成一个Markdown报告
6. 系统可以稳定运行
```

你会发现：

**你根本不需要告诉它代码应该怎么写。**

这才是你最应该培养的能力。

官方 Best Practices 还明确推荐复杂任务先使用 **Plan mode**，让 Codex 先调查、澄清和设计，再开始实现。

这个习惯对编程小白非常重要。

# ③ Codex CLI

官方：

https://developers.openai.com/codex/cli

你看到 CLI 不要害怕。

你不用现在学习 shell。

只需要理解：

> ChatGPT 是你跟 AI 对话。

而：

> **Codex CLI = AI 进入你的电脑项目里真正干活。**

Codex CLI 可以：

```text
读取文件
↓
理解项目
↓
修改文件
↓
运行程序
↓
发现错误
↓
修改错误
↓
运行测试
↓
继续修
```

官方 quickstart 的核心也是让 Codex 在本地 repository 里“explore → plan → edit → run tools → review”。

这就是 Agentic Coding。

你真正需要理解的不是：

> 怎样写 Python？

而是：

> **Codex现在正在我的电脑上做什么？**

这是两个完全不同的问题。

# 第二阶段：你开始创造“AI员工”

这一步开始会非常适合你。

## ④ AGENTS.md

官方：

https://developers.openai.com/codex/agent-configuration/agents-md

我希望你把它理解成：

# AI 员工手册

比如以后你的 AGENTS.md 可以写：

```text
# About me

The user is a non-technical entrepreneur.

Never assume she understands:
- coding
- terminal
- git
- API
- environment setup

Explain technical decisions in simple language.

# Working principles

Before coding:

1. Understand the business objective.
2. Create a plan.
3. Choose the simplest architecture.
4. Explain tradeoffs.

When implementing:

1. Make changes yourself.
2. Run tests yourself.
3. Fix errors yourself.

Do not ask the user to manually write code unless absolutely necessary.

# Security

Never expose API keys.

Never delete files without confirmation.

Never spend money or call expensive APIs without permission.
```

以后 Codex 每次打开这个项目，会先读取这些规则。OpenAI 官方文档就是这样设计 `AGENTS.md` 的：它可以在全局、项目和子目录层级给 Codex 持久化规则。

你会开始从：

> 每次教 AI 怎么工作

进化成：

> **一次设计AI员工行为，以后重复工作。**

这是非常重要的一步。

# 第三阶段：Skill

## ⑤ Build Skills

官方：

https://learn.chatgpt.com/docs/build-skills

这个对你的意义甚至可能比“学写代码”更大。

Skill 可以理解成：

> **把一套重复SOP变成AI能力。**

例如你以后可以做：

```text
market-opportunity-scout
```

里面写：

```text
每天：

搜索 Reddit
搜索 Google Trends
搜索 TikTok
搜索 YouTube
搜索 Product Hunt
搜索招聘网站

↓

识别异常增长需求

↓

分析：
需求强度
竞争程度
支付能力
用户画像
产品机会

↓

输出机会排行榜
```

Skill 的官方基本结构非常简单：

```text
my-skill/

SKILL.md
scripts/
references/
assets/
```

其中只有 `SKILL.md` 是核心必需文件；脚本、参考资料和资产可以按需要添加。

你可以把 Skill 理解成：

> SOP + 知识 + 工具 + 模板。

这一步以后，你已经不只是：

> “会用 Codex”

而是在：

> **搭建自己的AI组织能力。**

# 第四阶段：真正理解 AI Agent

## ⑥ OpenAI Agents SDK Quickstart

官方：

https://developers.openai.com/api/docs/guides/agents/quickstart

这一篇暂时不要第一天看。

等你把前面 5 个内容走完以后再看。

这里你开始真正理解：

# Agent 是什么？

最简单结构其实只有：

```text
Agent

=
Model
+
Instructions
+
Tools
+
Context
+
State
```

例如：

```text
Market Research Agent

Instructions
↓
寻找高利润市场需求

Tools
↓
Web Search
Reddit
Google Trends
Spreadsheet

Memory
↓
过去发现过什么

Output
↓
商业机会报告
```

OpenAI 的 Agents SDK Quickstart 第一件事就是创建：

```text
Agent
↓
instructions
↓
run
↓
result
```

然后才逐步增加 tools 和 specialist agents。官方甚至明确建议：**先做一个 focused agent，再逐步添加能力，不要一开始就做大型 multi-agent architecture。** 

这一点你一定要记住。

很多 AI 教程喜欢一上来：

> 10 Agent  
> CrewAI  
> AutoGen  
> LangGraph  
> supervisor  
> router  
> evaluator

很酷。

但对你来说很容易变成：

> 技术玩具。

你应该反过来：

```text
赚钱问题
↓
业务流程
↓
哪些步骤AI可以做
↓
一个Agent
↓
Tools
↓
Automation
```

# 第五阶段：MCP

## ⑦ MCP & Connectors

官方：

https://developers.openai.com/api/docs/guides/tools-connectors-mcp

这个概念你以后会经常听见。

不要被名字吓到。

MCP 你暂时理解成：

> **AI世界的USB接口。**

电脑为什么有 USB？

因为：

```text
电脑
↓
USB
↓
键盘
鼠标
硬盘
摄像头
```

Agent 也是一样：

```text
AI Agent
↓
MCP
↓
Gmail
Google Drive
Notion
Slack
CRM
Database
Browser
Stripe
Shopify
```

所以你想实现：

> Agent 帮我处理生活工作中的一切琐事

核心其实不是：

**模型有多聪明。**

而是：

**它能连接多少工具。**

OpenAI 已经把 MCP 和 Connectors 放进官方 Tools 体系，用于连接外部工具和数据源。

> Agent 像人一样使用电脑。

